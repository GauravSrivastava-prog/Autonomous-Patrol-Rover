2. Deep Dive: How We Explored & Used Webots

◈ What is Webots and Where is It Used Here?

Webots is an industry-standard open-source robotics simulator powered by the ODE (Open Dynamics Engine) physics library. Instead of building physical hardware that can break or burn motors, Webots allows us to model accurate kinematics, dynamics, friction, and sensor noise.

1. The Scene Graph Architecture

Everything in worlds/ai_arena.wbt is structured as a hierarchical tree of nodes. Every physical object has two main components:
• Shape: Visual appearance (PBR materials, color, roughness).
• boundingObject + Physics: What the physics engine uses to compute collisions, mass, inertia, and gravity.

2. The <extern> Controller Concept

In Webots, robot controllers can be embedded or external. We set controller "<extern>". This tells Webots: "Don't launch a process yourself; listen on a local IPC socket (port 1234) for an external Python script to take control."

3. The Python `controller` Package

We linked /Applications/Webots.app/Contents/lib/controller/python into our Python virtual environment. It provides direct Python bindings to Webots' C++ dynamic library (libController.dylib).

Webots Classes & APIs We Leveraged in Python:

Supervisor

controller.Supervisor

Unlike a standard Robot node which can only see its own onboard sensors, a Supervisor has omniscient administrative authority over the simulation.

  • robot.getSelf(): Grabs our robot's node handle in the Webots scene tree.
  • self_node.getPosition(): Reads exact ground-truth 3D coordinates (X, Y, Z).
  • trans_field.setSFVec3f([0, 0, 0.06]): Instantly teleports the robot back to origin.
  • self_node.resetPhysics(): Clears velocity and angular momentum on reset.

Camera

controller.Camera

Simulates an onboard optical RGB camera mounted to the front chassis.

  • camera.enable(timestep): Starts rendering camera frames every 32ms.
  • camera.getImage(): Returns a raw C memory buffer containing BGRA pixel bytes (320 × 240).
  • np.frombuffer(): Converts Webots raw bytes into an OpenCV matrix in micro-seconds with zero disk I/O.

DistanceSensor

controller.DistanceSensor

Two infrared rangefinder sensors (ps_left and ps_right) angled at ±17 degrees.

  • lookupTable [0 1000 0, 0.6 0 0]: Configures response curve (1000 when touching, 0 at 0.6m away).
  • ps_left.getValue(): Reads proximity value used by our obstacle avoidance state machine.

Motor (HingeJoint)

controller.Motor

Controls the left and right drive wheels along their rotational axes.

  • motor.setPosition(float('inf')): Crucial command! Puts the motor into velocity control mode rather than position/servo mode.
  • motor.setVelocity(rad_per_sec): Sets speed in radians/second for differential steering.

3. The 3 Control Modes Explained Simply

🧠 Mode 1: AI_PATROL

Goal: Autonomous exploration with obstacle avoidance.

  • Drives forward at default cruising speed (3.0 rad/s).
  • If ps_left > 600 (wall on left), slows left wheel and accelerates right wheel to steer right.
  • If ps_right > 600 (wall on right), steers left.
  • If both sensors trigger (approaching corner), executes a sharp reverse pivot turn.
  • Periodically initiates exploratory swerves to cover different zones of the arena.

🎯 Mode 2: AI_CHASE (Visual Servoing)

Goal: Vision-guided target intercept.

  • The camera detects Red, Green, or Blue targets via HSV segmentation.
  • Calculates horizontal steering error: dx = target_cx - (320 / 2).
  • Uses proportional visual servoing:
    left_speed = forward_v + Kp * dx
    right_speed = forward_v - Kp * dx
  • Automatically stops when target bounding box area exceeds threshold (robot has reached the target).
  • If no target is visible, spins in place to search the arena.

🕹️ Mode 3: MANUAL

Goal: Human-in-the-loop teleoperation.

  • Disables AI steering and hands control to the dashboard.
  • Responds to browser directional buttons or W / A / S / D keyboard presses.
  • Commands are sent via asynchronous HTTP POST requests to /manual/{cmd} with zero lag.

4. Professor Viva Questions & Exact Answers

Here are the most common questions robotics professors ask during project evaluations, along with the crisp technical responses:

Q1 Why did you use the `Supervisor` class instead of a standard `Robot` class in Webots?
"A standard Robot class in Webots simulates realistic physical limitations where the robot only has access to its onboard sensors. We enabled supervisor TRUE so that our mission control dashboard could obtain ground-truth telemetry (exact global X, Y coordinates and orientation) to plot on our 2D Radar Mini-Map and perform instant teleport resets via setSFVec3f() without needing to restart the Webots simulation process."
Q2 Why did you call `motor.setPosition(float('inf'))`?
"By default, Webots RotationalMotor devices operate in position control mode (like a robotic arm joint attempting to move to an angle). Setting the position target to infinity (float('inf')) switches the internal PID controller into velocity control mode, allowing the wheels to rotate continuously like vehicle tires with motor.setVelocity()."
Q3 How does the camera image transfer from Webots C++ to Python and then to the web browser?
"Webots renders the 3D scene using OpenGL/Metal on the GPU and stores pixel data in a native C++ BGRA memory buffer. Calling camera.getImage() gives us direct access to that buffer. We use np.frombuffer() to wrap those bytes into a NumPy array without copying data. OpenCV converts BGRA to BGR, draws our targeting HUD overlay, and compresses it to a JPEG byte array. Finally, FastAPI streams the JPEG frames as a multipart/x-mixed-replace MJPEG stream over an HTTP response to the browser's <img> tag."
Q4 What is the difference between a `Shape` node and a `boundingObject` in Webots?
"In Webots, Shape defines only the visual appearance (geometry and PBR material rendering for graphics). It has no physical collision. The boundingObject defines the simplified collision boundary for the physics engine (ODE). Separating visuals from collisions allows complex visual models to use simple boxes or cylinders for ultra-fast collision detection."
Q5 Why did you use differential drive instead of Ackermann (car-like) steering?
"Differential drive robots (two independent drive wheels + passive caster support) can perform zero-radius in-place turns (left_v = -right_v). In a compact 3m × 3m enclosed arena, zero-radius turning allows the robot to easily escape corners and immediately pivot toward visual targets, which Ackermann steering cannot do."
Q6 Why is there both YOLOv8 and HSV color detection in your vision pipeline?
"HSV color segmentation is deterministic, extremely lightweight, and computes high-frequency centroid errors (dx) for smooth visual servoing. YOLOv8 is a state-of-the-art deep learning model that detects generic real-world objects. We combine both: HSV provides the sub-millisecond control loop for target tracking, while YOLOv8 runs every 3rd frame to demonstrate deep learning inference on live robotic camera feeds."
Q7 Why did you configure the controller as `<extern>`?
"Setting controller "<extern>" decouples the simulation runtime from our AI environment. Instead of Webots trying to launch Python using its internal system paths, our external script launches inside our custom .venv with Apple Silicon optimizations and PyTorch hardware acceleration, connecting to Webots over local inter-process communication (IPC)."
